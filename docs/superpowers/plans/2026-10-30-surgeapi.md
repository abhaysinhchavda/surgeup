# SurgeAPI Implementation Plan

> **SUPERSEDED** by `TASKS.md` at the repo root (A+ scope, team of 3). Kept for history only — do not execute this file.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pay-per-call AI API on BSV mainnet where callers pay a live surge price (or bid above it) through HTTP 402, and the server serves the highest-paid job next.

**Architecture:** One Express server with free read routes (`/price`, `/state`, `/job/:id`) mounted before the BRC-103/104 auth + BRC-105 payment middleware, which guards `POST /job`. A pure in-memory `Market` owns pricing and the priority queue; a single worker drains it through a mock `runJob()`. Agents are Node scripts with their own wallet-toolbox wallets; the human pays from BSV Desktop through a Vite dashboard that proxies to the server.

**Tech Stack:** TypeScript, Node ≥ 22, Express 5, `@bsv/sdk` 3.2.1, `@bsv/wallet-toolbox` 2.14.9, `@bsv/auth-express-middleware` 2.2.9, `@bsv/payment-express-middleware` 2.1.9, Vite, Vitest, tsx.

**Spec:** `docs/superpowers/specs/2026-10-30-surgeapi-design.md` (copied in Task 1 from `D:\Cluade_WS\TUM_Blockchain_Hackathon\docs\2026-10-30-surgeapi-design.md`). Also binding: `AGENTS.md` at repo root.

## Global Constraints

- Package versions exactly as `AGENTS.md` / the starter kit `package.json` (copy it with its lockfile, don't re-resolve).
- Price constants: `baseSats = 100`, `k = 0.5`, `price = ceil(baseSats × (1 + k × queuedCount))`. Mock service time 2000 ms in `main.ts` (tests use small values).
- Charged price = the caller's `bid` (sats, integer). Unpaid first request with `bid < price()` → `400 { error: 'bid below surge price', priceSats }` before any payment. Paid retry (has `x-bsv-payment` header) only requires `bid >= baseSats`. Queue priority uses `req.payment.satoshisPaid`, never the body.
- Bid goes in the JSON body (`{ prompt, bid, label? }`) — no custom headers (AGENTS.md).
- Keys only in gitignored `.env`; wallet SQLite files in gitignored `.local/`. Never print, log, or commit a private key. The builder never asks the user for a key or recovery phrase.
- Network: mainnet (`chain: 'main'`). Explorer links: `https://whatsonchain.com/tx/<txid>`.
- Server port 8080, dashboard port 5173.
- Every money-moving command on mainnet (funding, demo runs, human payment) is run by the user, who approves each spend in BSV Desktop or explicitly OKs agent spends.
- `starter/` stays untouched as reference.

## Review Focus

1. Malformed bids (`"abc"`, `-5`, `150.5`, missing, string `"200"`) → 400, no payment taken. (Task 3 test `rejects malformed bids`)
2. Missing or huge prompt (empty, > 2000 chars) → 400 before payment. (Task 3 test `rejects bad prompts`)
3. Unknown job id → `404 { error: 'not found' }`. (Task 3 test `unknown job is 404`)
4. Surge price rising between challenge and paid retry must not fail a paid request. (Task 3 test `paid retry is accepted after surge rises`)
5. Dashboard with an empty queue and no served jobs renders "Queue empty" / "No jobs yet", not a crash. (Task 6 Step 3)

### Task 2: Market (pricing + priority queue)

**Files:** Create `src/market.ts`; Test `test/market.test.ts`

**Interfaces:**
- Produces:
```ts
export interface MarketConfig { baseSats: number, k: number }
export type JobStatus = 'queued' | 'running' | 'done'
export interface Job { id: string, caller: string, label: string, prompt: string, paidSats: number, txid: string, seq: number, enqueuedAt: number, status: JobStatus, startedAt?: number, doneAt?: number, result?: string }
export interface MarketSnapshot { priceSats: number, queueDepth: number, queue: Job[], running?: Job, served: Job[] }
export class Market {
  readonly cfg: MarketConfig
  constructor (cfg: MarketConfig, now?: () => number)           // now defaults to Date.now
  price (): number                                               // ceil(baseSats × (1 + k × queuedCount))
  enqueue (j: { caller: string, label: string, prompt: string, paidSats: number, txid: string }): Job
  next (): Job | undefined     // highest paidSats, ties → lowest seq; marks running, sets startedAt
  complete (id: string, result: string): void                   // marks done, sets doneAt
  get (id: string): Job | undefined
  position (id: string): number | undefined                     // 1-based among queued, in serve order
  snapshot (): MarketSnapshot  // queue in serve order; served = done jobs, newest first, max 20
}
```
Job ids: `crypto.randomUUID()`.

- [ ] **Step 1: Write failing tests** (`cfg = { baseSats: 100, k: 0.5 }`):
  - `price rises with queue depth`: empty → 100; 1 queued → 150; 2 → 200; after `next()` (1 queued) → 150.
  - `serves highest paid first, FIFO on ties`: enqueue paid 100 (a), 300 (b), 200 (c), 300 (d) → `next()` order b, d, c, a.
  - `position is 1-based in serve order`: enqueue 100 (a) then 300 (b) → `position(b) === 1`, `position(a) === 2`; after `next()` → `position(b) === undefined`, `position(a) === 1`.
  - `snapshot lists served newest first, capped at 20`: enqueue+next+complete 25 jobs → `served.length === 20`, `served[0].id` is the last completed.

### Task 3: Server app and worker

**Files:** Create `src/server.ts`; Test `test/surge.e2e.test.ts`

**Interfaces:**
- Consumes: `Market`, `MarketSnapshot` (Task 2).
- Produces:
```ts
export const MAX_PROMPT = 2000
export function createSurgeApp (provider: WalletInterface, market: Market): Express
export function startWorker (market: Market, runJob: (prompt: string) => Promise<string>, idleMs?: number): { stop: () => void }
export function mockRunJob (serviceMs: number): (prompt: string) => Promise<string>
```
Routes, in this order:
1. `express.json()`.
2. Free, before auth (plain `fetch` works): `GET /price` → `{ priceSats, queueDepth }`; `GET /state` → `market.snapshot()`; `GET /job/:id` → `{ id, status, position, result, waitedMs, paidSats, txid, label }` (`waitedMs = startedAt − enqueuedAt` once started) or `404 { error: 'not found' }`.
3. `POST /job` validation, before auth: `prompt` must be a non-empty string ≤ `MAX_PROMPT` → else `400 { error: 'bad prompt' }`; `bid` must satisfy `typeof bid === 'number' && Number.isInteger(bid) && bid > 0` → else `400 { error: 'bad bid' }`; no `x-bsv-payment` header and `bid < market.price()` → `400 { error: 'bid below surge price', priceSats }`; header present and `bid < market.cfg.baseSats` → same 400 with current price.
4. `createAuthMiddleware({ wallet: provider })`, then `createPaymentMiddleware({ wallet: provider, calculateRequestPrice: req => req.method === 'POST' && req.path === '/job' ? req.body.bid : 0 })`.
5. `POST /job` handler: `market.enqueue({ caller: req.auth.identityKey, label: typeof req.body.label === 'string' ? req.body.label.slice(0, 24) : req.auth.identityKey.slice(0, 8), prompt, paidSats: req.payment.satoshisPaid, txid: req.payment.txid })` → `{ jobId, paidSats, txid, position }`.

`startWorker`: async loop until stopped — `next()`; if a job, `await runJob(job.prompt)`, then `complete`; else wait `idleMs` (default 100). `mockRunJob` sleeps `serviceMs`, then returns `` `[mock AI] ${prompt.slice(0, 60)}` ``.
